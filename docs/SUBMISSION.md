# 원티드 AI Championship 2026 제출 초안 — 첫손님

> 제출 항목: 서비스 접속 링크 · 해결하려는 문제 · AI 활용 방식 · 사용한 AI 도구. 심사 기간(09.21~10.05) 동안 링크가 살아 있어야 함.

## 서비스명

첫손님 (First Customer) — 배포 전에 AI 손님 5명이 먼저 다녀갑니다

## 서비스 접속 링크

(배포 후 기입) https://cheotsonnim.vercel.app

## 한 줄 소개

주소 하나를 넣으면 AI 손님 5명이 실제 브라우저로 사이트를 직접 써 보고, 스크린샷을 근거로 리뷰·점검표·점수를 남기는 AI 미스터리 쇼퍼.

## 해결하려는 문제

AI 코딩 도구 덕분에 웹사이트를 만드는 비용은 거의 0이 됐지만, 만든 것을 실제로 써 보는 비용은 그대로입니다. 첫 사용자가 겪는 문제(핵심 버튼이 안 보임, 모바일에서 깨짐, 스크린리더로는 접근 불가, 팝업이 화면을 가림)는 만든 사람 눈에는 보이지 않고, 사람에게 사용자 테스트를 맡기면 며칠과 수십만 원이 듭니다. 그래서 대부분의 사이드 프로젝트·랜딩페이지·신규 기능은 "누가 써보기 전"에 배포됩니다.

첫손님은 그 첫 사용자 역할을 60~120초 안에 대신합니다. 코드를 읽고 추측하는 것이 아니라 진짜 Chromium으로 진짜 클릭을 하고, 리뷰의 모든 문장에 근거 스크린샷이 붙습니다.

## AI 활용 방식

1. **행동 계획**: Gemma 4가 첫 화면 스크린샷과 클릭 가능한 요소 목록(#번호·태그·보이는 글자·링크)을 보고, 손님의 목표와 행동 최대 4개를 JSON으로 계획합니다. 목표가 없으면 첫 방문자가 가장 자연스럽게 할 행동을 스스로 정합니다.
2. **실행과 재계획**: 실행기가 실제 브라우저에서 클릭·입력·키·스크롤을 수행하고 매 단계 스크린샷을 찍습니다. 막히면 현재 화면으로 한 번 재계획합니다(최대 6단계).
3. **손님 5명의 리뷰**: 스크린샷·행동 기록·점검표를 근거로 바쁜 손님, 어르신, 모바일, 스크린리더, 깐깐한 손님이 각자 렌즈로 리뷰를 쓰고, 매니저가 총평과 "이것부터 고쳐라" 3개를 씁니다. 존재하지 않는 사진 id를 인용하면 버립니다.
4. **AI가 하지 않는 일**: 사실 판정과 점수. HTTPS, 로드 시간, 콘솔 오류, alt 누락, 라벨 누락, 가로 스크롤, 탭 타깃 크기 등 18개 항목은 브라우저에서 직접 측정하고, 점수는 "손님 평점 60 + 점검표 25 + 미션 성공 15"의 고정 계산식으로 냅니다. AI가 점수를 느낌으로 매기지 않습니다.
5. **안전 규칙**: 공개 주소만 방문, 결제·삭제·탈퇴 클릭 금지, 비밀번호·카드 입력 금지, 합성 개인정보만 사용, 비밀번호 폼 미제출.

## 사용한 AI 도구

- Gemma 4 (`gemma-4-26b-a4b-it`, Google AI Studio API) — 서비스 런타임의 유일한 모델.
- Claude Code — 설계·구현·테스트·문서 작성.

## 왜 확장 가능한가

- 대상 제한이 없습니다. 어떤 공개 URL이든, 어떤 목표든 같은 파이프라인이 돕니다.
- 손님은 프롬프트 한 단락으로 추가됩니다(예: 해외 방문객, 어린이, 저사양 기기).
- CI 훅으로 붙이면 "PR마다 첫손님이 다녀간 리포트"가 됩니다. 에이전시·노코드 빌더·랜딩페이지 도구에 내장 가능한 API 형태입니다.

## 시연 시나리오 (60초)

1. 원티드 주소를 넣고 "손님 보내기" — 손님이 스스로 "채용 공고 확인하기"를 목표로 정해 2클릭 만에 상세 페이지 도달.
2. 실시간 화면: 손님이 지금 보는 스크린샷이 그대로 흐른다.
3. 리포트: 점수 링, 미션 결과, 손님 5명의 리뷰(근거 사진 클릭), 고칠 것 Top 3, 점검표, 계산식.
4. "링크 복사" → 공유 미리보기 카드(OG 이미지).
